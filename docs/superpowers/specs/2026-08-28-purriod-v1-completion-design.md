# Purriod 第一版完善设计

日期：2026-08-28

## 1. 目标

在现有原生微信小程序 TypeScript 工程上完成 Purriod 第一版，使“设置周期 → 记录经期 → 生成预测 → 查看日历 → 查看分析 → 删除数据”形成可验证的完整闭环。

第一版继续使用三个 Tab：经期、记录、我的。微信订阅消息、社区、文章内容、VIP、电商、复杂健康评分以及医疗建议或诊断不在本次范围内。

## 2. 验收范围

### 经期 Tab

- 展示今日周期状态、周期圆环、距离下次经期或预计结束的天数。
- 支持一键记录月经开始和月经结束。
- 展示今日记录的中文摘要。
- 无历史记录时提供明确引导。
- 预测明显过期时提示用户补充记录，不持续滚动出看似精确的新日期。
- 所有预测均标注为预计结果，不表达医疗结论。

### 记录 Tab

- 展示月历、实际经期、预测经期和预计排卵日。
- 点击日期后可查看摘要并进入每日记录编辑页。
- 每日记录支持流量、痛经、白带、心情、症状标签和备注。
- 支持编辑和删除单日记录。
- 空白默认记录不计入记录次数，也不在日历中显示状态。
- 提供独立分析页入口。

### 我的 Tab

- 支持周期长度和经期长度设置。
- 提供完整隐私说明、关于 Purriod 和清除我的数据入口。
- 清除操作必须删除云端和本地数据，失败时不得显示全部清除成功。

### 分析页

- 展示平均周期、平均经期和已记录周期数。
- 展示最近最多六个周期的周期长度趋势和经期天数趋势。
- 数据不足时展示清晰的空状态。
- 使用原生 WXML/WXSS 实现轻量图表，不引入大型图表依赖。

## 3. 总体架构

采用“本地即时保存 + 云端同步”的本地优先架构：

```text
页面
  ↓
业务服务（预测、分析、记录规范化）
  ↓
数据仓库（设置仓库、记录仓库）
  ├─ 本地缓存
  ├─ 待同步队列
  └─ 微信云数据库
```

页面不直接调用 `wx.cloud.database()`。云数据库访问、本地缓存、分页、合并和错误降级全部收口到数据仓库层。预测和分析保持为不依赖 `wx` 的纯函数，便于自动测试。

日常设置和记录直接通过用户权限受限的云数据库读写。清除全部用户数据通过一个 `deleteUserData` 云函数完成，云函数从微信运行上下文取得当前用户身份，并分页删除该用户的所有数据。

## 4. 云数据库设计

第一版只保留两个集合，不新增 `user_profiles`。

### `user_settings`

每位用户保存一条有效设置：

```ts
interface UserSettings {
  _id?: string;
  cycleLength: number;
  periodLength: number;
  schemaVersion: 1;
  createdAt?: Date;
  updatedAt?: Date;
}
```

默认周期长度为 28 天，经期长度为 5 天。第一版不保存提醒设置。

### `period_records`

每位用户每天最多保存一条有效记录：

```ts
interface PeriodRecord {
  _id?: string;
  date: string;
  isPeriodStart: boolean;
  isPeriodEnd: boolean;
  flow: "none" | "light" | "medium" | "heavy";
  pain: "none" | "mild" | "moderate" | "severe";
  discharge: "none" | "light" | "medium" | "heavy";
  mood: string;
  symptoms: string[];
  notes?: string;
  schemaVersion: 1;
  createdAt?: Date;
  updatedAt?: Date;
}
```

`_openid` 由微信云数据库写入，不由客户端传入。集合权限必须限制为用户只能读取、创建、修改和删除自己的文档。仓库同时记录云开发控制台所需的权限与索引配置步骤，部署前在控制台逐项验证。

### 查询与索引

- `period_records` 支持按 `date` 范围查询和升序排序。
- 预测只请求所需的最近记录，不依赖一次获取整个集合。
- 分析查询最近十二个月，并支持分页。
- 单日更新先在当前用户权限范围内按 `date` 查找，再更新或创建。
- 设置读取按更新时间选择唯一有效记录；若历史上出现重复设置文档，保留最新记录并清理多余文档。

## 5. 本地缓存与同步

本地保留三个逻辑区域：

- 用户设置缓存。
- 经期记录缓存。
- 待同步操作队列。

待同步操作包含实体类型、操作类型、实体键、载荷和本地修改时间。记录的实体键为日期，设置的实体键固定为 `settings`。同一实体的连续操作在发送前合并，避免重复写入。

### 保存流程

1. 校验并规范化输入。
2. 立即写入本地缓存。
3. 写入或合并待同步操作。
4. 更新页面，让用户立即看到结果。
5. 尝试同步云端。
6. 成功后移除待同步操作；失败时保留队列并显示非阻塞的“待同步”状态。

### 拉取与合并

1. 小程序启动、页面进入和网络恢复时触发同步。
2. 先推送本机待同步操作，再拉取云端最新数据。
3. 云端数据按实体键合并到本地；仍未成功推送的本地操作不得被覆盖。
4. 同一日期发生跨设备冲突时采用最后一次成功写入为准。第一版不提供冲突历史界面。
5. 云端不可用时继续读取本地缓存，不阻断记录。

### 删除单日记录

删除操作先在本地隐藏该记录，并加入删除队列。云端删除成功后移除队列；失败时保留待删除状态，防止下一次拉取把该记录重新显示出来。

## 6. 清除全部数据

“清除我的数据”需要联网完成，流程如下：

1. 展示二次确认并明确不可恢复。
2. 调用 `deleteUserData` 云函数。
3. 云函数从可信运行上下文获取当前用户的 openid。
4. 分页删除该用户的 `period_records` 和 `user_settings`。
5. 云端全部删除成功后，客户端清除本地缓存和待同步队列。
6. 三个 Tab 恢复默认状态。
7. 任一步失败时保留本地数据和重试能力，并显示具体失败提示。

客户端不得把 openid 作为删除目标参数传给云函数。

## 7. 预测算法

预测算法采用最近数据优先的简化方案：

1. 提取并去重经期开始日期，按时间升序排列。
2. 采用最近最多七个开始日期，得到最近最多六个周期间隔。
3. 只保留 18 至 45 天的有效周期间隔。
4. 没有有效间隔时使用用户设置的周期长度。
5. 有有效间隔时使用四舍五入后的平均周期。
6. 实际经期结束日期优先使用明确的结束记录；没有结束记录时使用设置的经期长度估算。
7. 下次经期开始日为最近一次实际开始日期加平均周期。
8. 预计排卵日为下次经期开始前 14 天，仅作为周期估算展示。
9. 如果预测经期窗口已经过去且用户没有新记录，状态改为“记录待更新”，不无限向后滚动预测。

预测结果包括：是否有记录、阶段名称、阶段键、今日文案、辅助文案、下次预计开始和结束日期、预计排卵日、平均周期及预测是否过期。

## 8. 经期区间和分析统计

经期区间根据开始、结束记录配对：

- 开始日期后遇到第一个合法结束日期时形成实际区间。
- 缺少结束日期时，在日历展示上最多按设置中的经期长度估算，但分析中标记为估算值。
- 未找到开始日期的单独结束记录不生成一个新周期。
- 同一天不能同时作为开始和结束；编辑时切换其中一项会关闭另一项。

平均经期优先使用完整实际区间。没有完整区间时回退到用户设置值，不能把只记录一天误算成一次完整的一天经期。

分析展示最近最多六个有效周期，按日期排序。少于两次经期开始记录时不绘制周期趋势，并提示继续记录。

## 9. 页面与模块调整

### 新增页面

- `pages/record-editor/index`：单日记录编辑与删除。
- `pages/analysis/index`：基础统计与趋势图。

### 现有页面调整

- `pages/period/index`：中文摘要、预测过期状态、同步状态和记录后的即时刷新。
- `pages/records/index`：保留月历与当日摘要，移除长表单，增加编辑和分析入口。
- `pages/profile/index`：保留设置、隐私政策、清除数据、关于 Purriod。
- `pages/settings/index`：通过设置仓库保存，并在返回后触发预测刷新。

### 模块拆分

- `utils/date.ts`：无时区歧义的日期运算。
- `services/period-prediction.ts`：预测纯函数。
- `services/period-analysis.ts`：经期区间和分析纯函数。
- `repositories/settings-repository.ts`：设置缓存与云端读写。
- `repositories/records-repository.ts`：记录缓存、范围查询和云端读写。
- `services/sync-service.ts`：队列合并、推送、拉取和网络恢复同步。
- `constants/options.ts`：记录选项及中英文展示映射。

旧的 `utils/storage.ts` 在迁移完成后删除，避免页面绕过新的仓库层。

## 10. 错误处理

- 本地保存失败：阻止离开并明确提示。
- 云端保存失败：本地数据保留，显示“已保存，待同步”，不显示云端成功。
- 云端读取失败：显示本地缓存，并保留轻量重试入口。
- 集合不存在或无权限：开发版打印可定位错误；正式版提示暂时无法同步。
- 删除全部数据失败：不清除本地健康数据，不显示成功状态。
- 页面所有加载流程使用 `try/finally` 保证 Loading 正常关闭。

## 11. 测试与验证

### 自动测试

预测与分析至少覆盖：

- 无记录。
- 一次开始记录。
- 两至七次规则周期。
- 异常周期过滤。
- 跨月、跨年和闰年。
- 有开始无结束。
- 有明确结束日期。
- 重复开始日期。
- 预测窗口已经过期。
- 修改设置后重新计算。
- 单独结束记录不生成周期。

数据层至少覆盖：

- 保存本地成功、云端成功。
- 保存本地成功、云端失败并进入队列。
- 重复保存同一天时队列合并。
- 待删除记录不会被拉取结果恢复。
- 分页查询合并。
- 清除云端失败时保留本地数据。

### 微信开发者工具回归

- TypeScript 编译无错误。
- 三个 Tab 和两个非 Tab 页面导航正确。
- 新用户、已有记录用户分别走查。
- 开始、结束、编辑、删除和设置修改后跨页面刷新正确。
- 断网记录、恢复网络、重新进入小程序后同步正确。
- 云端权限验证：用户不能读取或修改其他用户数据。
- 清除数据后本地与云端均无用户记录。
- iOS 和 Android 真机各验证一次。

## 13. 完成标准

以下条件全部满足才视为第一版完善完成：

- 三个 Tab 与设置、记录编辑、分析页面均可正常运行。
- 记录、预测、日历和分析对同一份数据给出一致结果。
- 无网络时可以记录，恢复网络后可以自动同步。
- 用户只能访问自己的云端数据。
- 单日记录和全部用户数据均可可靠删除。
- 自动测试和微信开发者工具回归通过。
- 第一版没有订阅消息、社区、内容、商业化和医疗诊断功能。
